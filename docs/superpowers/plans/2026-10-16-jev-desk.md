# Jev Desk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Screen-reading helpdesk triage agent on TypeSafe Jev with a Playwright runner (demo + eval) and a Chrome extension side panel.

**Architecture:** One isomorphic core (Jev client, in-page marks script, agent loop over an `io` adapter); two shells (Playwright runner, MV3 extension) supply `io`. A static demo helpdesk with 50 labelled tickets is the stage and the eval set.

**Tech Stack:** Node 24 ESM, `playwright` (only dependency, dev), vanilla HTML/CSS/JS, Chrome MV3.

**Spec:** `docs/superpowers/specs/2026-10-16-jev-desk-design.md` (read it — it is the authority).

## Global Constraints
- No dependencies besides `playwright`. ESM `.mjs` for Node modules; `core/marks.js` is a classic script.
- Jev: `POST {baseUrl}/v1/systemone`, model `jev-1.14.0`, headers `Authorization: Bearer <key>`, `content-type: application/json`, `TypeSafe-Danger-Zone-Images: true`. Price `42e-9` USD per input token.
- Hard spend cap $4 across the whole project (ledger `.jev-spend.json`). **Automated tests never call the real Jev** — they use `test/stub-jev.mjs`.
- Category keys and button labels exactly: refund "Refund", shipping "Shipping", billing "Billing", account "Account", order "Order change", damaged "Damaged item", wrong_item "Wrong item", spam "Spam". Other buttons: "Urgent", "Escalate to human".
- Helpdesk hooks: `[data-ticket-list]`, rows `[data-ticket-id]`, `[data-ticket-actions]`, `window.helpline.state()`; port 5180; `?reset` clears state.
- Viewport 1280×800 for runner screenshots.
- Demo helpdesk is called "Helpline"; never use Zendesk names or branding.

## Review Focus
- Jev returns a mark id that doesn't exist (e.g. `m14` when 9 marks) → escalate, never throw.
- Ticket with no attachment → `photo` should be `none`; `damage_box` ignored; no box drawn.
- Budget reached mid-run → loop stops cleanly, report still written with what was done.
- Extension on a page without `[data-ticket-list]` (any other site) → marks fall back to whole document, no crash.
- 429/5xx from Jev → retried; persistent failure skips the ticket and the run continues.

Agent details beyond the spec:
- Step 1 question keys: `next` (mark choice: "Which red label is on the topmost ticket row whose status is New in `screen`?"), `any_new` (noul).
- Step 2 question keys: triage keys + `btn_<categoryKey>` for each category ("Which red label is on the \"<Label>\" button in `screen`?"), `btn_urgent`, `btn_escalate`.
- Mark ids `m<i>` map to `marks[i-1].id`. Unknown → escalate (if `btn_escalate` valid) else skip with event `error`.
- `io.click` awaits; between steps call `io.wait(150)`.
- Events: `{type:'ticket', decision, clicked:[labels], latencyMs (sum of both calls), costUsd (delta)}`, `{type:'error', message}`, `{type:'budget'}`, `{type:'done', handled}`.

### Task 3: Playwright runner + stub Jev + e2e tests (Codex)

**Files:** Create `runner/run.mjs`, `test/stub-jev.mjs`, `test/e2e.test.mjs`, `reports/.gitkeep`.

**Consumes:** Task 1 exports; Task 2 `startServer`, helpdesk hooks.

- `runner/run.mjs` exports `async function run({ eval: bool, headed, limit, slow, budgetUsd, baseUrl, apiKey, ledgerPath = '.jev-spend.json', reportsDir = 'reports', log = console.log })` → `{report, reportPath}` and has a CLI (`--eval --headed --limit N --slow ms --budget usd`). API key from `JEV_API_KEY`. Budget = min(4, --budget) minus ledger spent. Viewport 1280×800, `page.addInitScript` / `addScriptTag` with `core/marks.js` after each navigation. io adapter per spec (`screenshot` = viewport PNG base64 with `hideOverlay()` before and `showOverlay()` after).
- Demo mode prints one line per ticket: `#1005  Damaged item  92%  auto  📸 damaged  412 ms  $0.00027`.
- Eval report: metrics listed in spec "Runner". Accuracy uses the agent's decisions joined to tickets by the opened row's `data-ticket-id` (agent records it: the io adapter remembers the last clicked `[data-ticket-id]`). Markdown table + JSON.
- `test/stub-jev.mjs`: `startStubJev({ truthFor })` → `{url, close, calls}`; a local HTTP server implementing `/v1/systemone` that, for tests, answers using a `truthFor()` callback the test supplies (it reads the current page state from Playwright), returns realistic shapes (`usage.input_tokens: 3000`). Mark questions are answered by the test via the page's `data-jev-mark` attributes.
- `test/e2e.test.mjs`: with the stub, `run({eval:true, limit:5, baseUrl: stub.url, apiKey:'test', ledgerPath: tmp})` → 5 tickets Triaged/Escalated in `helpline.state()`, report file exists with accuracy 100%, ledger written, budget stop works (`budgetUsd` tiny → stoppedBy budget, report still written).

### Task 4: Chrome extension (Antigravity)

**Files:** Create `extension/manifest.json`, `extension/background.js`, `extension/sidepanel.html`, `extension/sidepanel.js`, `extension/sidepanel.css`, `extension/icons/*.png` (16/48/128, simple generated), `test/extension.test.mjs`.

**Consumes:** `extension/core/{jev.mjs,agent.mjs,marks.js}` (via `npm run build:ext`), `test/stub-jev.mjs`.

- Background (module) imports `./core/jev.mjs` and `./core/agent.mjs`; implements `io` via `chrome.tabs.captureVisibleTab(windowId, {format:'png'})` and `chrome.scripting.executeScript({files:['core/marks.js']})` + `func` calls to `window.jevMarks.*`. Settings `{apiKey, budgetUsd:1, spentUsd, baseUrl}` in `chrome.storage.local`. Messages from the side panel: `scan`, `autopilot:start`, `autopilot:stop`; events streamed back via `chrome.runtime.sendMessage({type:'event', ...})`. `chrome.sidePanel.setPanelBehavior({openPanelOnActionClick:true})`.
- `scan`: runs only step 2 (triage + marks on `[data-ticket-actions]` or whole page), draws marks + damage box, does not click; returns the decision.
- Side panel UI per spec; lanes: Urgent, Refund, Shipping, Billing, Account, Order change, Damaged item, Wrong item, Spam, Needs a human. Cards show ticket subject — get it by adding `title` to the decision event: background reads `document.querySelector('h1,h2')?.textContent` of the tab after opening the ticket (DOM read only for labelling the card, never for decisions).
- `test/extension.test.mjs`: Playwright `chromium.launchPersistentContext('', {headless: false? → use channel 'chromium' with args --headless=new, --disable-extensions-except, --load-extension})`, set storage via the service worker (`context.serviceWorkers()`), stub Jev base URL, open helpdesk, open a ticket, trigger `scan` by evaluating in the service worker, assert a decision event and that marks exist on the page.
- [ ] build; tests green; do NOT commit.
